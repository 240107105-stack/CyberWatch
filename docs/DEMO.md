# Демонстрация CyberWatch на собеседовании

## Подготовка отдельной базы

Из корня проекта выполните:

```bash
python3 main.py --database /tmp/cyberwatch-demo.db --demo --check --report /tmp/cyberwatch-report.html
python3 main.py --database /tmp/cyberwatch-demo.db
```

Это отдельный файл, рабочая `cyberwatch.db` остаётся на месте. Команда `--demo`
добавляет учебные события и запускает анализ. Повторный запуск не дублирует демо.
Для полностью нового прогона используйте другое имя файла базы.

При стандартных настройках (пять неудач за десять минут, десять разных портов)
21 событие приводит к трём сигналам. Если в выбранной демо-базе вы меняли пороги
или добавляли другие события, результат может отличаться.

## Сценарий на 5–7 минут

1. **Обзор.** Покажите число событий, открытых сигналов и IP-источников.
   График отражает последние сутки. Объясните, что записи локальные и учебные.
2. **Журнал.** Найдите `203.0.113.45`. Покажите пять неудачных SSH-входов,
   за которыми следует успешный. Отметьте время события и адрес источника.
3. **Перебор.** В центре оповещений откройте сигнал о переборе. Покажите
   связанные события и объясните порог, окно и возможные ложные срабатывания.
4. **Успех после неудач.** Откройте второй сигнал. Его смысл — повод проверить,
   был ли успешный вход разрешён. Сам сигнал не доказывает компрометацию.
5. **Порты.** Найдите `198.51.100.23`: один источник обращается к 12 разным
   портам назначения. Двенадцать обращений только к одному порту не эквивалентны
   этому условию.
6. **Триаж.** Возьмите сигнал в работу. Добавьте заметку, например:
   «Учебный сценарий. Проверены связанные события; реальная сеть не затронута».
   Закройте сигнал и покажите историю статусов.
7. **Отчёт.** В разделе отчётов нажмите **Сохранить отчёт HTML**. Откройте файл:
   он содержит описание сигналов, события-доказательства, заметки и историю.
   Приложение не отправляет отчёт на внешний сервер.

## Наблюдение за файлом

Создайте отдельный `training-live.log` в удобной папке. В разделе наблюдения
выберите его, нажмите **Начать наблюдение**, затем допишите в файл строку:

```text
Failed password for analyst from 192.0.2.88 port 54000 ssh2
```

Завершите строку переводом строки и сохраните файл. Поскольку явного времени
в записи нет, временем события будет время её чтения. Приложение читает новые
строки выбранного файла; оно не наблюдает автоматически за всей сетью.

Для проверки правила допишите пять таких строк и запустите детекцию. Если
наблюдение автоматически вызывает детекцию в текущем режиме интерфейса,
сигнал появится без отдельного нажатия. После демонстрации остановите наблюдение.

## Импорт исторического журнала

В папке `examples` есть `auth.log`, `firewall.log` и `events.jsonl`. Импортируйте
их и запустите детекцию. Даты в примерах фиксированы; на графике последних суток
их может не быть, но историческая корреляция учитывает эти события. Повторный
импорт того же файла должен показать дубликаты, а не новые попытки входа.

## Что честно сказать о проекте

«Это локальный Mini SIEM на Python и SQLite. Я нормализую SSH-, UFW- и JSONL-логи,
сохраняю время и источник, обнаруживаю три типа подозрительных последовательностей
в заданном временном окне. Аналитик видит события-доказательства, ведёт заметки
и историю расследования. Правила и обработка логов проверяются тестами. Проект
учебный; промышленный сбор данных и автоматическая блокировка не реализованы».
