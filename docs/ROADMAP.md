# CyberWatch 2.0: восемь этапов

Цель — завершённое локальное приложение для портфолио SOC-аналитика, которое
можно запустить из PyCharm, проверить на воспроизводимых событиях и показать
на собеседовании. План составлен для текущего проекта; это не восстановленный
список из старой переписки.

| Этап | Результат | Как проверить |
| --- | --- | --- |
| 1. Архитектура | Интерфейс отделён от хранения, импорта, правил, наблюдения, отчётов и демо | `ui/app.py` вызывает сервисы из `services`; команды без окна используют те же сервисы |
| 2. База и настройки | Совместимое обновление старой SQLite-базы; сохранённые настройки; таблицы доказательств, заметок и истории | Тест миграции сохраняет прежние события и статусы; перезапуск сохраняет настройки |
| 3. Импорт | SSH, UFW и JSONL; исходное время, IPv4/IPv6, контроль повторного импорта | Импортировать примеры дважды: первый раз добавляются записи, второй раз считаются дубликаты |
| 4. Детекция | Перебор паролей; успех после серии неудач; множество портов назначения; временные окна и связи с событиями | В пустой базе демо даёт три сигнала со стандартными порогами; повторная проверка не создаёт копии |
| 5. Наблюдение | Новые строки выбранного файла; поддержка частичных строк, усечения и ротации | Запустить наблюдение, дописать строку с переводом строки, проверить появление события |
| 6. Расследование | Подробности сигнала, события-доказательства, заметки аналитика, изменение статуса и история | Взять сигнал в работу, добавить заметку, закрыть, перезапустить приложение и проверить сохранение |
| 7. Отчёт и демонстрация | Фильтрованный CSV; самостоятельный HTML без внешних ресурсов; отдельная демо-база | Открыть HTML офлайн; проверить сигналы, заметки и историю; CSV соответствует фильтрам |
| 8. Проверка и передача | Автоматические тесты, CLI-проверка, инструкция PyCharm, примеры и сценарий собеседования | Запустить unittest и `main.py --check`; пройти `docs/DEMO.md` |

## Технические решения

- Python 3.10+, Tkinter и SQLite: проект запускается без установки внешних пакетов.
- Изменения схемы добавляют данные и поля, не удаляя существующую рабочую историю.
- Обнаружение отделено от часов запуска: анализируется последовательность
  исторических событий внутри временного окна. Будущие записи исключены.
- Связанные события объясняют, почему появился сигнал. Изменение статуса
  фиксируется отдельно от исходных событий.
- Наблюдение читает выбранный локальный файл. Оно не требует изменения системных
  служб и не получает автоматически доступ к закрытым журналам.
- CSV нейтрализует ячейки, которые табличный редактор мог бы исполнить как формулы.
  HTML экранирует сообщения и заметки и не загружает внешние ресурсы.

## Что показать как навык

1. Нормализацию логов и отличие времени события от времени импорта.
2. Корреляцию событий по IP и времени, а также объяснимые ложные срабатывания.
3. Триаж: оценка доказательств, заметка аналитика и обоснованное закрытие сигнала.
4. Проверяемость: повторяемое демо, тесты граничных случаев и отчёт с доказательствами.

## Границы версии

Это не промышленный SIEM: нет распределённых агентов, ролевого доступа,
круглосуточного сервиса, очередей доставки, GeoIP/репутационных API и автоматической
блокировки атак. Эти возможности не входят в восемь этапов локальной версии 2.0.
Наличие сигнала означает совпадение с правилом и требует расследования.
