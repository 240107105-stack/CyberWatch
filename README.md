# CyberWatch 2.0 — локальный Mini SIEM

Настольное приложение для портфолио SOC-аналитика: импорт журналов,
обнаружение подозрительных последовательностей событий, расследование сигналов
и выгрузка отчёта. Python, Tkinter и SQLite; внешние пакеты не требуются.

## Запуск из PyCharm

1. Откройте папку **CyberWatch** как проект.
2. Выберите установленный Python **3.10 или новее** с поддержкой Tkinter.
3. В верхнем списке конфигураций рядом с зелёной кнопкой ▶ выберите **CyberWatch**.
4. Нажмите ▶. Откроется окно приложения.

Если конфигурация ещё не появилась, откройте `main.py` и выберите
**Run 'main'** в контекстном меню редактора. Рабочая папка — корень проекта.
Красные имена новых файлов в дереве PyCharm могут обозначать их статус в Git.

Для демонстрации сначала создайте отдельную базу из учебных сценариев:

```bash
python3 main.py --database cyberwatch_demo.db --demo --check
```

Затем выберите конфигурацию **CyberWatch Demo** или запустите:

```bash
python3 main.py --database cyberwatch_demo.db
```

В новой демо-базе будут 21 учебное событие и три сигнала. Базы не входят в Git;
обе конфигурации PyCharm хранятся в `.run/`. Пример отчёта:
[examples/demo-report.html](examples/demo-report.html).

Запуск в терминале из папки проекта:

```bash
python3 main.py
```

Проверка Tkinter, если окно не открывается:

```bash
python3 -m tkinter
```

На macOS Tkinter обычно входит в официальный установщик Python. Для чтения
логов используются обычные права текущего пользователя; запуск от root не нужен.

## Что можно делать

| Раздел | Возможности |
| --- | --- |
| Обзор | Реальные счётчики базы, график событий за последние 24 часа, быстрые действия |
| Журнал событий | Импорт, поиск по содержимому и источнику, фильтр приоритета, подробности события |
| Центр оповещений | Связанные события, заметки аналитика, статусы OPEN / ACKNOWLEDGED / RESOLVED и история изменений |
| Наблюдение | Чтение новых строк выбранного лог-файла, обработка дописанных строк и ротации |
| Правила | Настройка порогов перебора паролей, временного окна и количества разных портов; настройки сохраняются |
| Отчёты | CSV с текущими фильтрами и автономный HTML с сигналами, доказательствами и заметками |

## Первый сценарий

1. Нажмите **Добавить демо-события**. В пустой базе появится 21 учебная запись.
2. Нажмите **Запустить детекцию →**.
3. При стандартных настройках появятся три сигнала: перебор SSH-пароля, успешный
   вход после серии неудач и обращение одного источника ко множеству портов.
4. Выберите сигнал, просмотрите связанные события, возьмите его в работу,
   добавьте заметку и закройте после проверки.
5. В разделе отчётов сохраните HTML и откройте его обычным браузером.

Повторное добавление демо не размножает события. Повторная детекция сохраняет
статусы существующих сигналов. Если вы изменяли пороги правил, результаты демо
могут отличаться; для воспроизводимой проверки используйте отдельную базу.
Подробный сценарий для собеседования — [docs/DEMO.md](docs/DEMO.md).

## Работа без окна

```bash
# Проверка целостности и сводка базы
python3 main.py --check

# Отдельная демо-база: создание сценария, проверка и HTML-отчёт
python3 main.py --database /tmp/cyberwatch-demo.db --demo --check --report /tmp/cyberwatch-report.html

# Открыть эту же демо-базу в интерфейсе
python3 main.py --database /tmp/cyberwatch-demo.db

# Версия
python3 main.py --version
```

`--database` позволяет выбрать отдельную SQLite-базу. `--demo`, `--check` и
`--report` работают без окна и могут использоваться вместе. Обычный запуск
сохраняет данные в `cyberwatch.db` рядом с `main.py`.

## Форматы и время событий

- Текстовые SSH-логи с `Failed password`, `Failed publickey`, `Accepted password`
  и `Accepted publickey`; IPv4 и IPv6.
- Строки системного журнала с ISO-временем либо `Nov  1 10:00:00`.
- Строки UFW с полями `SRC=`, `DST=`, `DPT=` для анализа портов назначения.
- JSON Lines с полями `timestamp`, `source_ip`, `event_type`, `severity`,
  `message`, а при необходимости `destination_ip`, `destination_port`.
- CSV с колонками экспорта CyberWatch: исходное время и метаданные сохраняются.
- Учебные примеры лежат в папке [examples](examples).

Время с часовым поясом приводится к локальному времени компьютера. Если в строке
времени нет, используется время её импорта. Некорректное явно указанное время
не подменяется текущим. В syslog без года год определяется относительно текущей
даты с учётом перехода декабря в январь. Повторный импорт того же файла
пропускает уже сохранённые строки; одинаковые записи на разных строках остаются
отдельными попытками входа.

Детекция анализирует исторические события и их временные интервалы, а не только
последние минуты по настенным часам. Записи из будущего не участвуют в детекции.
График на обзоре показывает только последние 24 часа, поэтому после импорта
старого журнала он может быть пустым при наличии событий в таблице.

## База и резервная копия

При запуске существующая база обновляется добавлением таблиц, индексов и полей.
Имеющиеся события, сигналы и их статусы сохраняются. Перед ручным переносом
папки или обновлением проекта закройте приложение и скопируйте `cyberwatch.db`
в безопасное место. Не подменяйте рабочую базу демо-файлом.

## Проверки

```bash
python3 -m unittest discover -s tests -v
```

Тесты используют временные файлы и базы в памяти. Они проверяют миграцию старой
схемы, временные окна правил, повторные запуски, импорт IPv6, наблюдение за файлом,
историю расследования, экранирование HTML и защиту CSV от формул.

## Область применения

CyberWatch — учебное локальное приложение для демонстрации навыков SOC.
Сигналы требуют проверки аналитиком: неверный пароль или множество портов сами
по себе не доказывают атаку. Приложение не блокирует трафик, не собирает логи со
всей сети, не заменяет промышленный SIEM и не предоставляет многопользовательскую
аутентификацию. Геолокация и репутация IP не запрашиваются; адреса классифицируются
только по области адресации. Демонстрационные IP относятся к сетям документации.
Импортируйте только журналы, на чтение которых у вас есть разрешение.

План и критерии восьми этапов: [docs/ROADMAP.md](docs/ROADMAP.md).
